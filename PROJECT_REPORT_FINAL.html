ABSTRACT

Contemporary retail systems rely predominantly on Software-as-a-Service (SaaS) cloud models. While cloud solutions offer multi-branch accessibility, they force independent retail merchants to absorb recurring subscription fees, endure operational standstills during internet outages, and entrust sensitive store metrics to third-party databases.

Nexus POS is an enterprise-grade, offline-first desktop application developed to guarantee 100% operational uptime, zero subscription costs, and complete local data sovereignty. Built upon an asynchronous Electron, React 19, and SQLite3 multi-process architecture, the platform unifies real-time inventory management, rapid point-of-sale checkout with USB barcode scanner listeners, customer loyalty point tracking, operational expense management, and dual-mode invoice generation (Standard A4 PDF and 80mm POS Thermal Receipt rolls).

Security is enforced through Role-Based Access Control (RBAC) and cryptographic credential hashing using the scrypt algorithm with 16-byte random salts. Software quality and regression resistance are verified through an automated unit testing suite utilizing Vitest and React Testing Library. The resulting executable provides independent businesses with a self-sufficient, high-performance retail solution.

CHAPTER 1: INTRODUCTION

1.1 Background & Motivation

The retail industry has undergone massive digital transformation over the past decade. Traditional physical ledger systems have almost universally transitioned to computerized Point of Sale (POS) environments. However, the commercial market has shifted predominantly towards Software-as-a-Service (SaaS) cloud subscriptions. Products such as Shopify POS, Lightspeed, and Square require constant broadband connectivity and recurring monthly billing.

For independent neighborhood retailers, single-terminal convenience stores, and regional boutiques, this cloud model creates significant operational risks. Network blackouts cause register locks, delayed checkout lines, and abandoned purchases. Furthermore, small retail business models operate under lean margins that cannot sustain continuous licensing fees. Nexus POS was developed to offer a zero-dependency, locally contained desktop solution that delivers modern aesthetics and complete operational autonomy.

1.2 Problem Statement

  • Internet Fragility: Cloud checkouts fail entirely during ISP outages.
  • Cost Overheads: Recurring fees of $89+/month plus per-transaction cuts reduce merchant profitability.
  • Data Privacy Vulnerability: Financial ledgers, employee records, and customer contacts reside on third-party remote clouds.
  • Operational Inefficiency: Disconnected spreadsheets cause discrepancies between catalog counts and billed transactions.

1.3 Project Objectives

  1. Deliver an offline-first POS architecture running on local SQLite embedded storage.
  2. Incorporate hardware barcode scanning via keyboard emulation event listeners.
  3. Provide dual document compilation supporting both standard A4 and 80mm thermal receipt formats.
  4. Implement robust Role-Based Access Control (RBAC) backed by cryptographic scrypt password hashing.
  5. Include integrated CRM with automated loyalty rewards and operational expense logging.
  6. Validate system components through automated unit testing using Vitest.

CHAPTER 3: SYSTEM REQUIREMENTS SPECIFICATION (SRS)

3.1 Hardware Requirements

  • Processor: Dual-Core x86_64 CPU (1.8 GHz minimum).
  • RAM: 4 GB DDR4 minimum (8 GB recommended for multi-tasking).
  • Storage: 500 MB free hard drive space (SSD recommended).
  • Peripherals: Standard USB Barcode Scanner (HID Keyboard Emulation), 80mm ESC/POS Thermal Receipt Printer or standard A4 printer.

3.2 Software Environment

  • Operating System: Windows 10 / Windows 11 (64-bit), macOS Monterey+, or Ubuntu Linux 20.04+.
  • Runtime Environment: Electron v39.x (Node.js engine).
  • Frontend Stack: React 19.x, React Router DOM 7.x, Vite 7.x.
  • Database System: SQLite 3 (embedded file-based relational storage).
  • Cryptography: Node.js native crypto module.
  • Testing Engine: Vitest v5.x with JSDOM and React Testing Library.

3.3 Non-Functional Requirements

  • Performance: Checkout operations and local SQLite queries execute in sub-10 millisecond latency.
  • Reliability: Embedded SQLite engine guarantees full ACID compliance with zero risk of transaction loss during unexpected system power loss.
  • Security: All credentials stored as salted cryptographic hashes with constant-time equality comparisons.

CHAPTER 4: SYSTEM DESIGN & ARCHITECTURE

4.1 Multi-Process IPC Architecture

Nexus POS leverages Electron's decoupled multi-process architecture to enforce security sandboxing:

  • Main Process (Node.js): Manages native OS window lifecycle, file save dialogs for database backups, and direct SQLite database queries.
  • Renderer Process (React.js): Houses the modern glassmorphism dark-themed user interface, cart state, and PDF formatting routines.
  • Preload Bridge (`contextBridge`): Exposes an explicit, sandboxed API object (window.api) to the frontend, preventing arbitrary script injection while ensuring typed IPC transactions.

CHAPTER 5: DETAILED IMPLEMENTATION

5.1 Salted Cryptographic Password Security

User credentials are encrypted using the memory-hard scrypt algorithm with a unique 16-byte random salt generated per user:

// Main Process Authentication Logic (ipcController.js) const crypto = require('crypto') // Password Hashing on User Creation const salt = crypto.randomBytes(16).toString('hex') const key = crypto.scryptSync(password, salt, 64).toString('hex') const storedHash = `${salt}:${key}` // Timing-Safe Verification on Login const [salt, key] = user.password.split(':') const keyBuffer = Buffer.from(key, 'hex') const derivedKey = crypto.scryptSync(enteredPassword, salt, 64) const isMatch = crypto.timingSafeEqual(keyBuffer, derivedKey)

5.2 Hardware Barcode Keystroke Listener

Physical USB barcode scanners operate by emulating rapid keyboard entry terminated by a carriage return. The checkout screen implements a listener that filters keystrokes arriving within 500ms intervals:

// Billing.jsx Barcode Scanner Interceptor useEffect(() => { const handleKeyDown = (e) => { if (e.key === 'Enter' && barcodeInput.length > 2) { const product = products.find(p => p.sku === barcodeInput) if (product) addToCart(product) setBarcodeInput('') } else if (e.key.length === 1) { setBarcodeInput(prev => prev + e.key) setTimeout(() => setBarcodeInput(''), 500) } } window.addEventListener('keydown', handleKeyDown) return () => window.removeEventListener('keydown', handleKeyDown) }, [barcodeInput, products])

CHAPTER 7: CONCLUSION & FUTURE SCOPE

7.1 Conclusion

Nexus POS demonstrates that modern desktop retail software can achieve the responsive aesthetics of single-page web applications while maintaining the robustness, reliability, and security of an offline embedded database. By addressing the critical weaknesses of cloud subscriptions—such as network downtime, data privacy exposure, and high recurring fees—Nexus POS provides an autonomous, enterprise-grade solution for independent retail merchants.

7.2 Future Enhancements

  • Local Area Network (LAN) Multi-Terminal Synchronization: Enabling multi-counter supermarkets to share a centralized SQLite master node via WebSocket event streaming.
  • Direct Thermal Device Commands (ESC/POS): Integrating raw ESC/POS binary serial commands for automatic cash drawer kickout and hardware paper cutting.
  • Automated Cloud Snapshots: Providing optional end-to-end encrypted backup replication to Google Drive or AWS S3 for disaster recovery.
